# 电子公文流转智能体 — 异步接口改造设计方案

版本：V2.0  
日期：2026-10-22  
状态：已定稿，待实施

---

## 1. 背景与目标

### 1.1 现状

当前 `POST /api/v1/*` 接口为 **同步模式**：电子公文系统发起请求 → 智能体下载文件、调用 LLM → 同步返回结果。

```
EDOC ── POST /api/v1/document/classify ──► Agent
        （等待，可能 30s～180s）
EDOC ◄── {code, message, data} ◄─────────── Agent
```

### 1.2 目标

**彻底改为异步模式**（不做向后兼容），对齐《电子公文流转接口定义 V1.2》：

```
EDOC ── POST /api/v1/document/classify ──► Agent
        （立刻返回，毫秒级）
EDOC ◄── {code:0, task_id:linkid}
                                          Agent 后台处理：
                                          · 下载 file_url → 解析文档
                                          · 调用 LLM → 组装结果
                                          · POST callback_url → EDOC
                                          · 回调失败：重试 + 日志记录完整结果
```

### 1.3 核心要求

| # | 要求 | 说明 |
|---|------|------|
| R1 | 纯异步，不保留同步模式 | 所有 `/api/v1/*` POST 请求统一走异步 |
| R2 | 最大并发任务数限制 | `cfg.yml` 可配置，超限立即拒单 |
| R3 | 回调支持 HTTP/HTTPS | HTTPS 跳过证书验证 |
| R4 | 回调重试 + 日志 | 重试耗尽后日志必须打印完整返回信息 |
| R5 | 查询进行中任务 | 提供 API 查看当前运行中的任务 |
| R6 | 删除进行中任务 | 提供 API 取消/删除队列中的任务 |

## 2. 接口定义

### 2.1 受理接口（IF-02/03/04/06 — 改造后）

**请求体必须包含 `callback_url` 和 `linkid`**，其余字段不变。

**立即响应**：

```json
// 成功受理
{
  "code": 0,
  "message": "success",
  "task_id": "01a16276-2bac-7331-8d63-e5a9e0e89f80"
}

// 超限拒单
{
  "code": 2002,
  "message": "任务队列已满，当前处理中任务数 10/10（最大并发 5，最大排队 10），请稍后重试",
  "task_id": ""
}

// 缺少必填字段
{
  "code": 1001,
  "message": "缺少 linkid 或 callback_url",
  "task_id": ""
}
```

### 2.2 错误码补充

| code | 含义 |
|------|------|
| 2002 | 任务总数已满（处理中 + 排队 超过最大排队数） |

### 2.3 回调接口 IF-08

智能体处理完成后，向 `callback_url` 发起 POST：

| 项目 | 内容 |
|------|------|
| 请求方式 | POST |
| Content-Type | `application/json; charset=utf-8` |
| 认证 | `Authorization: Bearer {token}` |
| 协议 | HTTP 或 HTTPS |
| HTTPS | **跳过证书验证**（自签证书场景） |

**回调请求体（成功）**：

```json
{
  "code": 0,
  "message": "success",
  "task_id": "01a16276-2bac-7331-8d63-e5a9e0e89f80",
  "data": {
    "linkid": "01a16276-...",
    "need_human": false,
    "fail_reason": "",
    "doc_type": "company",
    "source_type": "group",
    "form_fill": { "file_no": "X保供办〔2026〕28号", ... },
    "opinion_text": "请刘总阅示。",
    "need_manual_restart": false,
    "ledger_data": null
  }
}
```

**回调请求体（LLM 失败）**：

```json
{
  "code": 5000,
  "message": "LLM 调用失败: context deadline exceeded",
  "task_id": "01a16276-...",
  "data": null
}
```

### 2.4 查询进行中任务接口

- **提供方**：电子公文流转智能体
- **用途**：查看当前运行中（pending + processing）的任务

| 项目 | 内容 |
|------|------|
| 请求 URL | `GET /api/v1/tasks` |
| 认证 | `X-Api-Key` 或 `Authorization: Bearer`（同现有 APITokenMiddleware） |

**响应**：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "total": 3,
    "max_concurrent": 5,
    "tasks": [
      {
        "task_id": "01a16276-...",
        "interface_path": "document/classify",
        "status": "processing",
        "callback_url": "https://edoc.example.com/callback",
        "elapsed_ms": 45000,
        "created_at": "2026-10-22 14:30:00"
      },
      {
        "task_id": "b1c2d3-...",
        "interface_path": "document/route",
        "status": "pending",
        "callback_url": "https://edoc.example.com/callback",
        "elapsed_ms": 0,
        "created_at": "2026-10-22 14:30:15"
      }
    ]
  }
}
```

### 2.5 删除进行中任务接口

- **提供方**：电子公文流转智能体
- **用途**：取消/删除队列中的任务

| 项目 | 内容 |
|------|------|
| 请求 URL | `DELETE /api/v1/tasks/{task_id}` |
| 认证 | `X-Api-Key` 或 `Authorization: Bearer`（同现有 APITokenMiddleware） |

**规则**：

- `pending` 状态的任务：直接删除，不会回调
- `processing` 状态的任务：**不支持删除**（LLM 调用进行中，无法中断），返回 409
- `success`/`failed`/`completed`/`callback_fail` 状态的任务：返回 404

**响应示例**：

```json
// 成功删除
{ "code": 0, "message": "任务已取消", "task_id": "xxx" }

// processing 中的任务不允许删除
{ "code": 1001, "message": "任务正在处理中，无法取消", "task_id": "xxx" }

// 不存在
{ "code": 1001, "message": "任务不存在或已结束", "task_id": "" }
```

## 3. 架构设计

### 3.1 整体架构

```
                              ┌──────────────────────────────────────────────────┐
                              │                 doc_flow_agent                     │
                              │                                                    │
  EDOC ── POST /api/v1/* ───►│  ai_call.go (入口)                                  │
                              │    │                                               │
                              │    ├─ 校验 linkid、callback_url                     │
                              │    ├─ 检查当前运行任务数 ≥ max? → 拒单 {code:2002}   │
                              │    ├─ 写入 async_tasks 表 (status=pending)          │
                              │    ├─ 入队 task_channel                             │
                              │    └─ 立即返回 {code:0, task_id:linkid}             │
                              │                                                    │
                              │  GET /api/v1/tasks ───► 查询 running/pending 任务   │
                              │  DELETE /api/v1/tasks/:id ► 删除 pending 任务       │
                              │                                                    │
                              │           task_channel (buffered chan)              │
                              │           │                  │                      │
                              │     ┌─────┼─────┐     ┌──────┼──────┐              │
                              │     ▼     ▼     ▼     ▼      ▼      ▼              │
                              │  Worker  Worker  Worker  ...                     │
                              │     │                                               │
                              │     ├─ 更新状态 processing                          │
                              │     ├─ 下载 file_url                                │
                              │     ├─ 解析文档                                     │
                              │     ├─ 渲染 prompt                                  │
                              │     ├─ 调用 LLM                                     │
                              │     ├─ 更新状态 success/failed                      │
                              │     │                                               │
                              │     └─ POST callback_url ────────► EDOC (HTTP/HTTPS)│
                              │        ├─ 成功 → status = completed                 │
                              │        └─ 失败 → 重试(最多N次) → 耗尽: 日志打印结果   │
                              └────────────────────────────────────────────────────┘
```

### 3.2 并发控制（两层限制）

```
cfg.yml:
  sys.max_concurrent_tasks: 5    ← 第一层：Worker 数量 = 同时处理的任务数
  sys.max_pending_tasks: 10      ← 第二层：任务总数上限（处理中 + 排队中）

                     ┌────────────────────────────┐
                     │  running = pending + processing  │
                     │  max_concurrent = Worker 数      │
                     │  max_pending    = 任务总数上限     │
                     └─────────────┬──────────────┘
                                   │
        POST 请求 ──► 统计 running 任务数
                        │
                  running < max_pending? ──Yes──► 入队，返回 {code:0}
                        │
                       No
                        │
                        ▼
                  返回 {code:2002}
                  "当前处理中任务数 10/10（最大并发 5，最大排队 10）"
```

**两层含义**：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `sys.max_concurrent_tasks` | 5 | Worker 数量，也就是**同时在调用 LLM 的任务数** |
| `sys.max_pending_tasks` | 10 | **任务总数上限**（`pending + processing`），超过这个数直接拒单 |

- `max_concurrent_tasks` 决定 channel buffer 大小和 Worker 数量
- `max_pending_tasks` 决定最多能排多少任务（含正在处理的）
- 排队任务数 = `max_pending_tasks - max_concurrent_tasks`（即 channel 里最多排多少个）
- 任务完成后进入终态（`success`/`failed`/`completed`/`callback_fail`），不占 `max_pending_tasks` 名额
- **两个值都可以不同**：比如 `max_concurrent=3, max_pending=20`，允许 3 个同时跑、最多排 20 个

### 3.3 任务状态机

```
                  ┌──────────┐
                  │  pending  │  已入队，等待 Worker 取出
                  └────┬─────┘
                       │ Worker 取出
                       ▼
                ┌──────────────┐
                │  processing  │  正在下载/调 LLM
                └──┬────────┬──┘
                   │        │
              LLM 成功    LLM 失败
                   │        │
                   ▼        ▼
            ┌─────────┐  ┌────────┐
            │ success │  │ failed │   ← 阶段性终态，不再占并发名额
            └────┬────┘  └───┬────┘
                 │           │
            callback      callback
                 │           │
            ┌────┴────┐  ┌──┴──────┐
            │         │  │         │
            ▼         ▼  ▼         ▼
       ┌──────────┐  ┌──────────────┐
       │completed │  │callback_fail │  ← 最终态
       └──────────┘  └──────────────┘
                         │
                         ▼
                   日志 ERROR 级别
                   打印完整回调 body
```

## 4. 回调机制

### 4.1 HTTP 客户端

```go
var callbackHTTPClient = &http.Client{
    Transport: &http.Transport{
        TLSClientConfig: &tls.Config{
            InsecureSkipVerify: true,  // HTTPS 跳过证书验证
        },
    },
    Timeout: 30 * time.Second,
}
```

### 4.2 重试策略

| 配置 | 默认值 | 说明 |
|------|--------|------|
| `sys.max_concurrent_tasks` | 5 | 最大并发任务数 |
| `sys.callback_url_token` | — | 回调 Bearer 认证 token |
| `sys.callback_retries` | 3 | 回调失败最大重试次数 |
| `sys.callback_retry_interval_sec` | 2 | 重试基础间隔（秒），指数退避：2s → 4s → 8s |

重试条件：

- 网络错误（DNS 解析失败、连接拒绝、超时等）
- HTTP 状态码 ≥ 500 或 == 0
- HTTP 状态码 < 500（如 4xx）**不重试**，视为终态

### 4.3 日志要求

```
# 回调成功
INFO  callback_success  task_id=xxx  callback_url=https://...  status=200  attempt=1

# 回调重试
WARN  callback_retry  task_id=xxx  callback_url=https://...  status=502  attempt=1/3  next_in=2s

# 回调耗尽重试（必须打印完整 body）
ERROR callback_exhausted  task_id=xxx  callback_url=https://...  attempts=3  status=502
      response_body={"code":0,"message":"success","task_id":"xxx","data":{...}}

# LLM 成功但回调失败 — response_body 必须含完整业务数据
ERROR callback_exhausted_llm_success  task_id=xxx  response_body={"code":0,...完整LLM结果...}
```

## 5. 数据模型

### 5.1 async_tasks 表

```sql
CREATE TABLE IF NOT EXISTS async_tasks (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id         TEXT UNIQUE NOT NULL,            -- = linkid
    interface_path  TEXT NOT NULL,
    request_body    TEXT NOT NULL,
    callback_url    TEXT NOT NULL,
    status          TEXT NOT NULL DEFAULT 'pending', -- pending/processing/success/failed/completed/callback_fail
    output_result   TEXT DEFAULT '',                 -- LLM 原始输出 JSON
    error_message   TEXT DEFAULT '',
    elapsed_ms      INTEGER DEFAULT 0,
    retry_count     INTEGER DEFAULT 0,               -- 回调重试次数
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

## 6. 处理流程

### 6.1 入口（ai_call.go）

```
POST /api/v1/*interfacePath
  │
  ├─ 读取 body
  ├─ 查找 interface 配置
  ├─ 提取 linkid → 缺失? → {code:1001}
  ├─ 提取 callback_url → 缺失? → {code:1001}
  ├─ 检查 running 任务数 >= max_pending_tasks? → {code:2002}
  ├─ 创建 AsyncTask (status=pending) → 写入 DB
  ├─ 发送到 task_channel (buffer = max_pending_tasks)
  └─ 返回 {code:0, message:"success", task_id:linkid}
```

### 6.2 Worker 处理（async_worker.go）

```
Worker goroutine 从 task_channel 取任务
  │
  ├─ 更新状态 processing
  ├─ 下载所有 file_url → 解析文档
  ├─ 渲染 prompt template
  ├─ 调用 LLM
  │    ├─ 成功 → 记录 output_result, status=success
  │    └─ 失败 → 记录 error_message, status=failed
  ├─ 更新 DB
  │
  └─ 回调 callback_url
       │
       ├─ status=success → body 带完整 LLM 结果
       ├─ status=failed  → body {code:5000, message:...}
       │
       └─ 重试循环:
            ├─ 网络错误 / HTTP ≥ 500 → 重试
            ├─ HTTP < 500 → 不重试，记录 callback_fail
            ├─ 成功 → status=completed
            └─ 耗尽 → status=callback_fail → ERROR 日志打印 response_body
```

### 6.3 删除任务

```
DELETE /api/v1/tasks/:task_id
  │
  ├─ task 不存在 / 状态为 success/failed/completed/callback_fail
  │    → {code:1001, message:"任务不存在或已结束"}
  │
  ├─ task 状态为 processing
  │    → {code:1001, message:"任务正在处理中，无法取消"}
  │
  └─ task 状态为 pending
       → 从 DB 删除
       → {code:0, message:"任务已取消", task_id:xxx}
```

> 注意：pending 任务在 channel 里，删除后 Worker 取出时会发现 DB 中已不存在，直接跳过。
